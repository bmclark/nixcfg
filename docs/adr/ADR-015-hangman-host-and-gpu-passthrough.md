# ADR-015: Hangman host and GTX 1650 passthrough to Windows 10 guest

## Status

Proposed (draft — not yet implemented or installed)

## Context

The Dell Optiplex 9020 (hostname: hangman) (i7-4790, 32 GB RAM, GTX 1650) currently runs Aurora
and dual-boots Windows 10. Goals:

- Unify all machines on the existing nixcfg flake (see ADR-001 architecture).
- Replace the dual-boot Windows 10 with a KVM guest, duplicating the existing
  install into a disk image so Windows runs alongside Linux instead of
  requiring a reboot.
- The GTX 1650 is passed through to the Windows guest; the Linux host runs
  on the i7-4790's integrated HD 4600 (i915), which is sufficient for a
  Wayland tiling WM.

## Decision

### Host module

Add `hosts/hangman/` following the maverick pattern:

- `default.nix` — entry point importing configuration, disko, hardware scan,
  and `../common/default.nix`.
- `configuration.nix` — hostname `hangman`, systemd-boot, NetworkManager
  (wired), PipeWire, greetd/tuigreet, SSH, firewall (SSH only), Tailscale.
  No TLP/fprintd/TrackPoint (laptop-only hardware config stays in maverick).
- `disko.nix` — declarative disk layout (see below).
- `hardware-configuration.nix` — generated by `nixos-generate-config` at
  install time; placeholder until then.

### Disk layout (disko, LUKS2 + btrfs)

ZFS was evaluated and rejected for this host: its strengths (raidz,
send/recv, native encryption) don't apply to a single 238G SSD, while its
costs (hostId, kernel-module coupling, ARC competing with the pinned RAM of
the Windows guest) do. ZFS is deferred to the future server project.

```
sda (GPT, managed by disko — sdb/sdc untouched)
├─ sda1  1G    FAT32 ESP, /boot (umask=0077)
└─ sda2  100%  LUKS2 ("crypted", allowDiscards)
    └─ btrfs
        ├─ /root     → /         (compress=zstd,noatime)
        ├─ /home     → /home
        ├─ /nix      → /nix      (noexec; store is disposable)
        └─ /var-log  → /var/log
zram swap (memoryPercent=25), same policy as maverick — no disk swap.
```

LUKS unlock: passphrase at console (the 9020 has TPM 1.2 only, no TPM2
auto-unlock). If unattended reboots become a need, add dropbear SSH unlock
in initrd as a follow-up.

Install: boot NixOS ISO, then
`sudo nix run github:nix-community/disko -- --mode destroy,format,mount ./hosts/hangman/disko.nix`
(DESTROYS /dev/sda only), then `nixos-install --flake .#hangman`.

Host graphics: Intel i915 out of the box; no Nvidia driver on the host.

### VFIO / passthrough

- Enable Intel VT-d IOMMU (`intel_iommu=on`).
- Bind the GTX 1650 (and its HDMI audio function) to `vfio-pci` at boot via
  `boot.kernelParams = [ "vfio-pci.ids=<gpu-id>,<audio-id>" ]` — IDs read
  from `lspci -nn` at install time.
- `virtualisation.libvirtd.enable = true` with QEMU session for bclark,
  `programs.virt-manager.enable = true`.
- Windows 10 guest: duplicate the existing dual-boot install by imaging the
  Windows partition to a qcow2/raw file (`dd` or `qemu-img convert`) and
  attaching it to the VM. Alternatively pass the physical Windows disk
  through by block device if it remains in the machine.
- Looking-glass is explicitly out of scope for v1; use a normal SPICE/VNC
  console first, add it later only if the console experience is limiting.

### VM definition

Libvirt domain XML is not natively declarative in NixOS. v1 keeps the domain
definition in virt-manager (imperative but exportable). The XML export gets
committed to `hosts/hangman/vms/win10.xml` as the source of truth so the VM
can be re-created with `virsh define`.

## Risks / open items

1. **IOMMU groups.** 4th-gen Intel consumer platforms (Haswell, Q87 chipset)
   often have poor IOMMU group isolation. If the 1650 shares a group with
   other devices, options are: ACS override (`pcie_acs_override=pcie_acs_multifunction`,
   kernel taint, mild security tradeoff) or an ACS-capable PCIe slot check.
   Must be verified on hardware before committing to the design.
2. **Windows reactivation.** Moving the install into a VM is a hardware
   change; the Windows 10 license (likely OEM) may not reactivate. Accept
   the risk or keep the physical dual-boot disk untouched as fallback.
3. **HD 4600 host graphics** are fine for Sway/Hyprland compositing but no
   gaming on the host — acceptable, gaming is the guest's job.
4. **Unstable channel.** The flake pins `nixos-unstable`; this host inherits
   that. A separate ADR should decide stable vs unstable fleet-wide.

## Migration order

1. ~~Verify IOMMU groups~~ — preflight (2026-10-13) confirmed VT-d enabled in
   BIOS (DMAR parsed, IRQ remapping active). Remaining: reboot Aurora with
   `intel_iommu=on` on the cmdline and inspect `/sys/kernel/iommu_groups`
   for group isolation of 01:00.0/01:00.1.
2. Image the Windows 10 disk (`/dev/sdb`, PNY 250GB, self-contained GPT
   layout) to `/dev/sdc` (500GB HDD) or external storage — safety net and
   VM seed. Disk plan: sda → NixOS, sdb stays Windows (pass to VM by block
   device or convert to qcow2), sdc → bulk storage.
3. Fresh NixOS install on the Optiplex from this flake (`hosts/hangman`):
   disko wipe of sda, `nixos-install --flake .#hangman`.
4. VFIO + libvirt + Windows guest, iterate.
5. Post-install: add `hangman` A record to the `tail.bclark.net` CoreDNS
   zone (standing tailnet convention — same change as node enrollment).
